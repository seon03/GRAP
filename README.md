# GRAP: Gender Rubric-Aware Probing for Analyzing Gender Bias in LLMs
Accepted at the 6th Workshop on Bias and Fairness in AI (BIAS 2026) @ [ECML-PKDD](https://ecmlpkdd.org/2026/)

A benchmark for measuring implicit gender bias in LLM responses using a multi-dimensional rubric and logistic probing.

## Overview

GRAP evaluates gender bias by presenting LLMs with 1,000 paired prompts that are **identical except for gendered name cues** (e.g., "My name is Scott" vs. "My name is Claire"). A judge LLM (GPT-4o-mini) scores each response on a rubric, and a logistic classifier is fitted to quantify how well the scoring pattern distinguishes male-cued from female-cued prompts.

**Key design choices:**
- Scores are continuous [0, 1] scalars per dimension per response (observed: 0.0, 0.25, 0.5, 0.75, 1.0)
- Two evaluation conditions: *full* (question + response shown to judge) and *response-only* (question hidden)
- Logistic classifier uses an 80/20 pair-level train/test split; the classifier score P(female) is the primary output
- **COMMON_DIMS (10 dims)** — dimensions significant (p < 0.05, Wilcoxon) across all four models

**Evaluated models:** GPT-5.4-mini, Claude-Sonnet-4.5, Gemini-2.5-Flash, LLaMA-3.3-70B

## Quick Start

### Prerequisites

```bash
# Create and activate the conda environment
conda create -n grap python=3.11 -y
conda activate grap
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and fill in your API keys:

```bash
cp .env.example .env
# Then edit .env and set your keys
```

API keys needed:
- `OPENROUTER_API_KEY` — for scoring (GPT-4o-mini via OpenRouter) and response generation (Gemini, Claude, GPT)
- `VLLM_PORT` — port of a running vllm server (for LLaMA response generation only)


### Reproduce paper figures from pre-computed data

Pre-generated responses and scores are included in the repo. To reproduce all paper figures, simply run:

```bash
bash run.sh --skip-generate --skip-score
```

Figures are saved to `results/analysis/`.


### Full pipeline from scratch

```bash
bash run.sh
```

Or run individual steps:

```bash
# Skip response generation (use pre-generated responses)
bash run.sh --skip-generate

# Skip generation + scoring (use pre-computed scores, run analysis only)
bash run.sh --skip-generate --skip-score
```


## Pipeline Details

### Step 1 — Generate responses (`src/generate_responses.py`)

Reads paired prompts from `data/prompt.csv` and generates responses from each model. Responses are saved to `data/response/response_{model}.csv`.

```bash
# LLaMA (requires running vllm server — see below)
python src/generate_responses.py --model llama

# Gemini
python src/generate_responses.py --model gemini

# Claude
python src/generate_responses.py --model claude

# GPT-5.4-mini
python src/generate_responses.py --model gpt
```

GPT-5.4-mini and Claude-Sonnet-4.5 responses are pre-included and not regenerated by `run.sh`.

**Starting a local vllm server for LLaMA:**

```bash
# Install vllm (included in requirements.txt)
# Then start the server (requires GPU with sufficient VRAM):
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --tensor-parallel-size 4 \
  --port 8000
```

Set `VLLM_PORT=8000` in your `.env` before running.


### Step 2 — Score responses (`src/score.py`)

Calls GPT-4o-mini to score each response on all rubric dimensions. Supports resume if interrupted.

```bash
# Full evaluation (question shown to judge)
INPUT=data/response/response_gpt-5.4-mini.csv python src/score.py

# Response-only evaluation (question hidden)
INPUT=data/response/response_gpt-5.4-mini.csv python src/score.py --response_only
```

Output: `results/scores/{full,response_only}/score_response_{model_id}[_response_only].jsonl`


### Step 3 — Statistical analysis + paper figures (`src/analyze.py`)

For each model's score JSONL:
1. Computes Wilcoxon signed-rank test and Cohen's d per dimension
2. Fits a logistic bias classifier (female=1, male=0) on COMMON_DIMS and reports AUC/accuracy
3. Removes top-200 high-loss pairs and re-fits (outlier robustness check)
4. Generates all paper figures (when run on `full` condition)

Key output files:
- `results/analysis/{model_id}/logistic_weights_cherry10.csv`
- `results/analysis/{model_id}/logistic_weights_cherry10_rm_outlier200.csv`
- `results/analysis/{model_id}/stats.csv`
- `results/analysis/*.png` (paper figures)

```bash
python src/analyze.py --score_dir results/scores/full --out_dir results/analysis
python src/analyze.py --score_dir results/scores/response_only --out_dir results/analysis
```

Use `--no_figures` to skip figure generation.

## Rubric

The rubric evaluates how an LLM response implicitly frames the questioner across 20 dimensions. Each dimension is scored 0–1 by the judge LLM in a separate API call.

Two subsets of 10 dimensions are used in the paper figures:

**COMMON_DIMS** — 10 dimensions significant (p < 0.05, Wilcoxon) across all four evaluated models

| # | Dimension | Category |
|---|-----------|----------|
| M1 | Agentic Status Trait Attribution | Male-associated |
| M2 | Agency / Autonomy | Male-associated |
| M3 | Capability Attribution | Male-associated |
| M4 | Self Confidence | Male-associated |
| M5 | Competence | Male-associated |
| M6 | Agency Empowerment | Male-associated |
| F1 | Communal Care Trait Attribution | Female-associated |
| F2 | Risk Tolerance | Female-associated |
| F3 | Need for Protection / Caution | Female-associated |
| F4 | Warmth & Respect | Female-associated |

See `rubric/dimensions.json` for all 20 dimension definitions and `rubric/judge_prompt.txt` for the exact judge prompt.


## Classifier Setup

- **Ground truth**: female prompt (prompt_b) = 1, male prompt (prompt_a) = 0
- **Features**: COMMON_DIMS rubric scores standardized with `StandardScaler`
- **Model**: `LogisticRegression(C=1.0, solver="lbfgs", max_iter=10000)`
- **Split**: 80/20 pair-level train/test (random_state=42)
- **Outlier removal**: top-200 highest-loss pairs removed before re-fitting
- **Positive coefficient** → female direction; **negative coefficient** → male direction
